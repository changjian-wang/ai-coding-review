## 1. 开发依据与交付目标

以[已确认原型](./prototypes/review-vnext/index.html)和[产品需求规划](./REVIEW-VNEXT-PRD.zh-CN.md)为基准，实现真实 VS Code 扩展闭环：

**选择 Repository 与 PR/分支 → 提供需求 → AI 整理理解与检查清单 → 人工确认 → 业务链审查与反证 → 有边界的结论。**

PR Reviewer 反馈在同一个工作区完成：**读取完整讨论 → 核实 → 修复或解释/澄清 → 验证与交付 → 预览 Reply → 按授权 Resolve 并核对远端结果。**

- 原型确定信息架构、交互和判断边界；其中固定案例、模拟进度、演示测试、假提交和发布结果不能进入正式实现。
- 保持三块准备、三阶段流程、一次确认后开始，不恢复逐文件启动、多次核对或逐材料用途分类。
- 延续 VS Code、现有 Copilot 模型与 GitHub CLI，不新增服务端、账号体系、图数据库或无关依赖。
- 优先交付一条真实纵向闭环，再补齐全部视图与反馈写回；不是先完成静态界面，再把分析作为最后一步。

## 3. 分阶段开发与验收

### M0：领域契约、迁移与评测准备

**交付**

- 定义 Repository/PR/head/base、源码与材料快照、已确认理解、业务链单元、发现、关键未知、运行状态及反馈发布状态之间的关联。
- 统一引用、失效和结果版本规则；规范“公开远端状态”与“本地分析/草稿”的分离。
- 设计存储 schema 版本与迁移测试：旧注释、处置、草稿和历史保留，但不自动迁移为新需求审查通过；不覆盖同名目录仓库。
- 建立需求矛盾、跨文件组合缺陷、上游保障充分/失效、证据不足的固定正反例与标注规则；记录当前模型效果基线。

**退出条件**

确定性状态与迁移测试通过；评测样本、标签及关键未决标准可执行。语义效果和资源阈值在留出集评估前冻结，不凭空承诺数值，也不为等齐全部样本而阻止基础开发。

### M1：真实 Repository、PR/分支与源码版本

**依赖：M0 的身份和快照契约。**

- 从已打开/用户选择的本地 Git 仓库开始，绑定明确 GitHub 仓库、账号及 PR；首次切片不新增任意远端仓库自动克隆。
- 实现 PR 变更、分支相对基线的变更、分支全量快照；明确文件的纳入原因和读取/核查状态。
- 范围读取优先使用指定 Git 对象，不因下拉选择就 checkout。缺少对象、fork 来源、无权限、空差异、删除/重命名和不可读文件均有明确处理。
- 代码、Diff、搜索和关联证据必须对应同一目标快照。LSP 只在版本匹配时使用；不匹配时用目标快照证据或明确受限，不能偷偷查询另一分支。
- 涉及切分支、worktree 或修复落地时先明确目标和授权，保护未提交改动；本地修改不能冒充已推送的 PR head。
- 用最小真实准备视图承接范围，不等待全套工作台重排。

**退出条件**

真实仓库下三种范围可复现，head/base 与文件内容一致；更换仓库、对象或提交后旧结果失效，脏工作树不被覆盖；新范围不会继承另一 PR 的批准或修复状态。

### M2：需求读取、AI 理解与一次确认

**依赖：M0；确认适用范围依赖 M1。**

- 支持粘贴 Markdown、读取本地 Markdown/TXT，以及真实授权链接。普通 HTTP/HTTPS 页面与可授权 GitHub 内容分开处理；访问失败、重定向越界、超限和不支持格式显式提示。
- 不把“只有演示链接可读”带入正式扩展，不把没有读取/分析成功说成没有需求。PDF/Word 等未支持格式不伪装成功。
- 保存原文、来源、版本和逐字引用；Markdown 预览不改原文，不执行 HTML 或自动请求图片。
- 通过现有模型接口真实生成目标、约束、验收条件、推导检查点和待核实前提；校验结构及引用有效性，不能擅自添加硬阈值或从现有代码反推需求。
- 人工修订、补充、排除和恢复留痕，一次“确认需求并开始审查”形成版本化基线；确认理解不证明需求正确。
- 没有明确需求时允许技术审查并持续标注“需求一致性未评审”；无模型、拒绝授权或调用失败保留材料，不自动产生确认结果。

**退出条件**

三种输入的真实读取、模型理解、出处核对、修订和重新确认跑通；修改材料、范围或原文使相关确认失效。无需多层勾选才能开始。

### M3：需求感知的业务链审查与一键编排

**依赖：M1、M2；复用现有分析器和证据收集。**

- 一次启动范围任务，按相关行为组织分析，不依赖用户逐文件打开或滚动完源码。
- 按判断需要读取完整逻辑与调用、状态、配置、schema、测试和异步边界；长文件分段且记录覆盖，不能把前缀截断当成整文件完成。
- 双向校验需求与实现，主动找上游保障和反证；全局阶段能独立发现组合缺陷，即使局部候选为空。
- 检查业务链之间的共享状态与契约；发现范围外直接相关问题时注明证据/新增审查对象及理由，不无限顺手扫全仓。
- 输出实现缺陷、需求缺陷、待核实、已排除及合理取舍；类型、严重度、归因和确定性分别表达。
- 实现真实完成/失败/取消/预算受限/待重审、局部重试及迟到结果隔离；缺证据不能静默转无问题。

**退出条件**

首条真实纵向闭环完成：M1 的真实代码 + M2 已确认理解 → 可追溯业务链判断 → 有边界的本地结论。配对样本同时验证发现能力和误报推翻，不以原型案例或单次模型输出代替效果评测。

### M4：源码主场工作区与结论门禁

**依赖：M1–M3；最小视图随前面阶段逐步接入。**

**当前状态：开发切片已实现并通过上述验证；既有 Reviewer 反馈和真实模型语义效果仍按 M5–M7/M0 验收，不以本轮 UI 或受控适配器测试替代。**

- 按原型完成准备/审查/结论三阶段；左侧业务/发现/PR 反馈/文件，中间源码/Diff/原文，右侧需求、影响、证据与处置。
- 阅读关联文件保留当前问题；复用修复预览/应用/撤销、注释、搜索、模型选择、双语及窗口恢复。
- 在宿主状态层分别计算批准、要求修改和评论能力，而非只禁用按钮；有效部分结果可反馈，关键未决和未完成范围禁止完整批准。
- 明确“需求修订不等于实现修复”“已评论不等于已解决”“已阅读不等于审查完成”，新旧所有命令入口保持一致。
- 持久化范围/需求/依赖版本、运行和处置；恢复后核对有效性，更新摘要与导出报告。

**退出条件**

真实 Extension Development Host 中完成三阶段闭环和重载恢复；内容/需求变化、取消、模型错误和受限结果均不能绕过门禁。阅读进度仍可辅助显示，但不再是业务正确性的证明。

### M5：Reviewer 反馈读取与处理

**依赖：M0/M1 后可先实现只读；完整处理依赖 M3/M4。**

- 通过现有 gh/账号适配读取完整 review threads、每个会话的分页评论、普通 PR 评论和总体 Review，保留 thread/comment/review 原始 ID、权限、原位置与版本。
- PR 自动同步；分支只在显式关联匹配 PR 后读取。同步失败保留旧快照和错误，不用空列表冒充没有反馈。
- 单独呈现 Reviewer 来源；AI 判断需修复、已有保障可解释、待澄清及新增需求建议，不能自动把评论变验收标准。
- 复用修复/撤销，多个会话可关联同一根因；记录实际验证方式及结果。需要提交/推送时明确文件集、Repository、PR head、权限及用户授权，不能带入无关工作树改动。
- 未执行测试时写清未执行；未验证/未交付可回复进度，不得回复“修复已完成”并关闭。

**退出条件**

真实只读同步与本地处置跑通；Outdated、Resolved、已改、已验证、已推送及已回复分别记录；新回复、依赖或 head 变化使相关本地证明失效。

### M6：真实 Reply / Resolve 与可靠恢复

**依赖：M5 的稳定原始 ID、权限和修复证据。**

- 对原会话追加 Reply，或明确更新本工具自己已发布且可编辑的回复；普通评论/总体意见使用引用回复，不伪造 Resolve。
- 预览目标账号、仓库、PR、原会话、内容和是否 Resolve；发布前刷新 head、权限及新消息，快照不一致先核对。
- 将“发布回复 → 确认已公开 → Resolve → 回读”作为可恢复步骤持久化；超时结果未知先查询，不假定成功，也不盲目重发。
- 尊重用户已有 Pending Review，不擅自发布、替换或丢弃；回复成功但 Resolve 失败只重试 Resolve。
- 批量操作逐会话预览和汇报部分失败；默认不自动勾选全部 Resolve。已经公开的状态不因本地重分析、切换 PR 或重载而消失。
- Resolve/重新打开不冒充 Reviewer Approve，不自动撤销 Request changes。

**退出条件**

适配层故障测试及用户明确授权的测试 PR 联调通过：网络超时、草稿、重复点击、部分失败、权限变化、新评论和新提交均准确恢复，不串回复或重复发布。未授权前不对真实 PR 写入。

### M7：完整验收与上线准备

**依赖：M0–M6；回归随各阶段进行，不集中到最后补测。**

- 覆盖 PRD 的 FR-01 至 FR-14、AC-01 至 AC-42；旧会话迁移、切换账号/Repository/PR、模型中断和大范围预算受限专项回归。
- 固定源码、需求、模型标识与资源边界，分别报告精确率、严重问题召回、合理取舍误报、系统性发现、关键未知误阻断、延迟与估算 Token。
- 在冻结的留出集上验证，不以降低召回换精确率，不把大量待核实当作低误报；阈值未冻结或结果未达标就不宣称完成。

- 确定新流程切换与 schema 回退边界，保留必要历史；验证后再决定是否保留临时旧流程回退入口，不长期维护两套分析核心。

**退出条件**

确定性红线、已冻结的效果/资源门槛及真实宿主/授权 GitHub 联调全部满足，才进入独立的发布确认。本计划不自动发 Marketplace 版本或合并到 main。
